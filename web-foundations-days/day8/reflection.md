# Day 8 — Course Reflection

The most difficult concept in this course was system capacity estimation and understanding how an application behaves when traffic increases. Initially, I found it challenging to move beyond calculating average requests and understand why peak traffic matters. I improved by practising calculations involving daily active users, requests per second, storage requirements, and peak traffic. Working on the SnapShare assignment also helped me understand the importance of explaining how different components work together rather than simply drawing an architecture diagram.

Based on the feedback I received on my capstone, I would improve the operational explanations of my designs. I learned that a system design document must explain how data moves through the application, how failures are handled, and why particular architectural decisions are made. For example, I would give more attention to request flows, database transactions, concurrency control, and architectural trade-offs. I would also verify that every required section is complete before submitting an assignment.

Next, I want to learn more about backend development, particularly building REST APIs, database transactions, concurrency control, and authentication. I am also interested in learning how cloud services, caching, message queues, and deployment tools are used in real production systems.

This course has helped me understand that building software is not only about writing code. It also involves designing systems that remain reliable, secure, and efficient as they grow.
